# Docs site conventions

Applies to everything under `docs-site/`. The engine's conventions are the repo
root `CLAUDE.md`; this file is the docs-site half.

- **Isolated toolchain.** `docs-site/` has its own `package.json` /
  `node_modules` and never touches the engine's pinned TypeScript — the build
  oracle is toolchain-sensitive (root `CLAUDE.md`), so keep the two installs
  separate. Dev/build: `cd docs-site && npm ci && npm run dev` (or
  `npm run build`).
- **It is a CI gate.** The site deploys as a sibling at `/big-break/docs/` from
  the same Pages workflow (`.github/workflows/pages.yml`), and `npm run build`
  here must pass before a merge to main.
- **Drift-proof by construction — keep it that way.** Never hand-copy engine
  facts into prose:
  - Reference pages are autogenerated by TypeDoc from `js/types.ts` +
    `js/engine.ts`.
  - Prose samples are transcluded from real pack source via `?raw` +
    `// #region` markers. A missing region throws, so the build fails loudly
    rather than shipping a stale sample — that failure mode is the feature.
  - Twoslash type-checks inline samples.
- Editing a pack's `#region` markers is comment-only — golden-safe.
